# The Marked Bench Leaderboard

This directory defines the public submission format for benchmark results.

The leaderboard is intentionally evidence-first. A valid entry needs a full
JSON report generated by the benchmark runner, not only a claimed score.

## Valid Submission Checklist

- The report validates with `marked-bench --validate-report PATH`.
- The suite cases match `suites/marked_bench_contradiction_standard_v0_1_0.json`.
- The report includes the full canonical `suite_cases` block.
- The report includes one `case_results` entry for every canonical case.
- The reported aggregate metrics recompute exactly from `case_results`.
- The submitted suite ID and suite version match the leaderboard track.
- The submission includes the report SHA-256 digest.
- Any non-default detector, prompt, model, or rule configuration is documented.

## Local Validation

```bash
marked-bench --validate-report baselines/contradiction_engine_v0_1_0.json
```

For an installed package, generate a report with:

```bash
marked-bench --system-name "my-system" --report my-system-report.json
```

Build a leaderboard from validated reports:

```bash
marked-bench --build-leaderboard baselines/*.json --leaderboard-output leaderboard/leaderboard_v0_1_0.json
```

For the adversarial track:

```bash
marked-bench --build-leaderboard baselines/always_none_adversarial_v0_2_0.json baselines/contradiction_engine_adversarial_v0_2_0.json --leaderboard-output leaderboard/leaderboard_adversarial_v0_2_0.json
```

For the multi-hop track:

```bash
marked-bench --build-leaderboard baselines/always_none_multihop_v0_3_0.json baselines/contradiction_engine_multihop_v0_3_0.json --leaderboard-output leaderboard/leaderboard_multihop_v0_3_0.json
```

For the controls track:

```bash
marked-bench --build-leaderboard baselines/always_none_controls_v0_4_0.json baselines/contradiction_engine_controls_v0_4_0.json --leaderboard-output leaderboard/leaderboard_controls_v0_4_0.json
```

## Baseline

The first baseline is the packaged symbolic `ContradictionEngine`. It is a
reference implementation for the report format and validator, not the ceiling
for future submissions.

The `AlwaysNoneDetector` baseline is intentionally weak. It exists as a sanity
check that the benchmark rewards actual contradiction classification over
always predicting `none`.

The adversarial leaderboard intentionally starts with the symbolic baseline
below a perfect score. That leaves room for stronger neural, symbolic, and
hybrid systems to show measurable improvement.

The controls leaderboard is a false-positive stress track. It should expose
systems that over-call contradictions on compatible paraphrases, scoped
negative claims, harmless elaborations, and ordinary time shifts.

Future leaderboard entries should compare against this baseline and disclose
whether they use symbolic rules, model prompting, fine-tuned classifiers, or
hybrid systems.
